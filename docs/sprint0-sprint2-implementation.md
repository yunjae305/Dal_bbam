# 관광 공모전 MVP · Sprint 0~2 구현 기준

작성 기준: 2026-07-24
정본 요구사항: `요구사항명세서(관광).docx`

## 기술 결정

- 웹 클라이언트는 Next.js 16 App Router와 React 19를 유지한다.
- 영속 저장소는 기존 Supabase/Postgres를 유지한다. 명세서의 MongoDB 표기는 현행 아키텍처로 대체한다.
- 공모전 MVP는 설치 가능한 PWA를 기본 제출물로 한다. 네이티브 패키지가 심사 필수일 때만 Capacitor 래퍼를 별도 Sprint로 추가한다.
- 관광 원천 데이터는 Supabase 동기화본 → TourAPI → 내장 샘플 순서로 조회한다. 스탬프처럼 영속성이 필수인 기능은 DB 동기화 장소에서만 성공한다.

## 배포 전 필수 작업

1. Supabase migration을 파일명 순서대로 적용한다.
2. `npm run sync:tour`로 스탬프 대상 장소를 DB에 동기화한다.
3. 운영 환경에 32자 이상의 `JWT_SECRET`을 설정한다.
4. `/api/health`의 readiness 항목을 점검한다.
5. 실제 모바일 브라우저에서 위치 권한과 Kakao 허용 도메인을 확인한다.
