# 달밤 · 경주 여행 PWA — 제품 개요

> 발표와 인수인계에 쓰는 정본 소개 문서다. 기능 목록뿐 아니라 **왜 그렇게 만들었는지**를 함께 적는다.
> 마지막 갱신 2026-09-19. 화면용 발표 자료는 [product-overview.html](product-overview.html).

## 1. 한 줄 소개

**달밤은 경주에 온 여행자가 지도앱·번역앱·메모장을 오가지 않고 한 화면에서 여행을 끝내도록 만든 모바일 웹앱(PWA)이다.**
관광지 정보는 한국관광공사 TourAPI, 지도·길찾기는 카카오를 쓴다. 설치 없이 브라우저로 쓰고, 원하면 홈 화면에 설치한다.

- 운영 주소: https://dal-bbam.vercel.app
- 구현 범위 기준: [요구사항명세서(관광).docx](<../요구사항명세서(관광).docx>) v1.1 (기능 요구사항 33개, 비기능 14개)

## 2. 누구를 위한 앱인가

| 대상 | 상황 | 달밤이 푸는 문제 |
|---|---|---|
| 외국인 개별 여행자(FIT) | 한국어를 못 읽고, 문화재 설명은 배경지식이 필요하다 | UI 4개 언어(한·영·일·중), 그림 중심 화면, 문화재 해설 |
| 국내 역사·문화 여행객 | 가 볼 곳은 많은데 동선을 짜기 번거롭다 | 조건만 고르면 코스와 시간표가 나오고, 그대로 일정이 된다 |
| 가족·단체 | 아이와 함께 즐길 거리가 필요하다 | GPS 스탬프 투어, 배지·리워드 |

**설계 원칙 세 가지**

1. **다른 앱을 열게 하지 않는다.** 검색·지도·길찾기·일정·기록을 한 앱에서 끝낸다.
2. **지어내지 않는다.** 관광 정보는 공공 데이터 원문에 근거하고, AI가 만든 문장은 그렇다고 밝힌다.
3. **끊겨도 쓸 수 있다.** 여행지에서 네트워크가 불안정해도 마지막으로 본 관광 정보는 남는다.

## 3. 기능

### 3.1 홈과 카테고리 (FR-HOME)

문화유산·관광지·맛집·숙박·축제·자연·체험으로 나눈 입구, 최근 7일 조회수 기반 인기 관광지, 언어 전환 버튼을 한 화면에 둔다.

**왜:** 처음 들어온 사람에게 "무엇부터 볼지"를 정해 주기 위해서다. 검색어를 떠올려야 하는 앱은 외국인에게 특히 불친절하다. 카테고리는 TourAPI 분류 코드에 맞춰 두어 데이터가 늘어도 그대로 동작한다.

### 3.2 지도·장소 상세·길찾기 (FR-MAP)

- 카카오 지도 위에 관광지 핀과 군집 표시, 카테고리 필터, 지도 확대·축소·현재 위치 버튼
- 장소 검색: 앱이 가진 관광지를 먼저 보여 주고 카카오 장소 결과를 뒤에 붙인다
- 출발지·도착지를 정하면 **도보·대중교통·자전거·자동차 네 가지를 한 번에 비교**한다. 각 수단의 소요 시간, 거리, 도착 예정 시각, 대중교통 요금·환승 횟수를 함께 보여 준다
- 경로는 지도에 선으로 그리고, 턴바이턴 안내를 펼쳐 볼 수 있다. 안내 한 줄을 누르면 지도가 그 지점으로 이동한다
- 실시간 내비게이션이 필요하면 같은 경로로 카카오맵 앱·웹을 연다
- 장소 상세: 사진, 소개, 운영 시간, 연락처, 리뷰, 국가유산 정보

**왜:** "지도는 보여 주되 길찾기는 다른 앱에서" 하는 여행앱이 많다. 이동수단을 고르는 일 자체가 여행자의 의사결정이라, 네 수단을 나란히 비교하게 만든 것이 이 앱의 지도 화면이 존재하는 이유다. 실제 주행 안내처럼 음성으로 길을 읽어 주는 기능은 카카오맵 앱이 훨씬 잘하므로, 그 지점에서만 넘긴다.

### 3.3 여행 장바구니와 일정 (FR-CART, FR-SCH)

마음에 든 곳을 담고(찜), 담은 것을 골라 날짜별 일정으로 보낸다. 일정에서는 장소 추가·순서 변경·체류 시간 조정·시간 재배치·삭제가 되고, 타임라인과 캘린더 두 가지로 본다. 일정은 링크로 공유한다.

**왜:** 여행 준비는 "고르기 → 묶기 → 순서 정하기"의 반복이다. 이 흐름을 메모장과 지도앱으로 나눠 하던 것을 한 앱에 넣었다. 순서를 바꾸면 시각을 다시 계산해 주는 것도 같은 이유다.

### 3.4 코스 추천 (FR-CRS)

여행 목적·기간·동행·속도·교통수단·관심사를 고르면 코스가 나온다. 저장하면 내 코스가 되고 공유 링크가 생긴다. 테마별 큐레이션 코스(신라 천년 역사 / 달빛 야경 산책 / 경주 미식)도 제공한다.

**왜:** 처음 오는 사람이 가장 막히는 지점이 동선이다. 추천은 두 갈래로 동작한다. 규칙 기반 추천이 기본이고(관심사 배분, 도보 가능 거리, 대표 문화재 우선), 여기에 Gemini를 얹어 장소 선택과 추천 이유를 다듬는다. AI 응답이 검증을 통과하지 못하면 규칙 기반 결과로 되돌아가므로 **추천이 실패해 빈 화면이 나오는 경우가 없다.**

### 3.5 스탬프 투어 (FR-STAMP)

승인된 관광지 9곳에서 GPS로 방문을 인증한다. 반경 밖이거나 위치 정확도가 낮으면 거절하고, 현장 QR 체크포인트로 한 번 더 확인할 수 있다. 테마(역사·미식)를 완성하면 배지와 디지털 리워드를 준다.

**왜:** 관광지를 "본다"에서 "모은다"로 바꾸면 체류 시간과 재방문이 늘어난다. 위치를 서버에서 검증하는 이유는 집에서 스탬프를 찍는 것을 막기 위해서다. 원시 위치 기록은 저장하지 않는다.

### 3.6 여행자 커뮤니티 (FR-COM)

사진을 올린 여행 후기, 꿀팁 게시판, 맛집·숙소 별점 리뷰, 북마크, 신고와 차단.

**왜:** 공공 데이터에는 없는 정보(지금 줄이 긴지, 주차가 되는지)는 여행자끼리 주고받는 편이 빠르다. 업로드 사진과 글은 검사를 거치고, 신고와 차단, 관리자 신고 큐를 함께 두어 문제 글이 남지 않게 했다.

### 3.7 문화재 쇼츠와 방문자 스토리 (FR-SNS)

세로형 짧은 영상으로 문화재를 소개하는 화면이다. **영상은 준비 중이라 지금은 "쇼츠 영상은 추후 추가 예정입니다."를 4개 언어로 안내한다.** 같은 화면의 방문자 스토리는 동작한다. 최근 올라온 방문자 사진으로 스토리 초안을 만들어 주고, 사람이 고쳐서 올린다.

**왜:** 문화재 설명문은 읽히지 않는다. 짧은 영상과 여행자의 사진이 훨씬 먼저 눈에 들어온다. 영상이 없는 상태에서 빈 피드를 보여 주는 대신 안내를 띄운 것은, 없는 것을 있는 척하지 않기 위해서다. 영상을 등록하고 스위치(`FEATURE_SHORTS`)만 켜면 바로 열린다.

### 3.8 문화재 해설과 음성

장소 상세에서 해설을 읽고 들을 수 있다. 해설은 TourAPI 소개문에 근거해 만들고, 음성은 기기 내장 음성으로 읽는다.

**왜:** 해설은 사실이 틀리면 안 되는 영역이라 원문 근거를 벗어나지 않게 했다. 서버에서 음성 파일을 만드는 대신 기기 음성을 쓰는 것은 비용과 응답 속도 때문이다.

## 4. AI를 어디에 썼고, 왜 거기까지만 썼나

| 쓰는 곳 | 모델 | 하는 일 |
|---|---|---|
| 코스 추천 | Gemini 3.1 Flash-Lite | 후보 40곳 중에서 고르고 순서·체류 시간·추천 이유를 쓴다 |
| 방문자 스토리 초안 | Gemini 3.1 Flash-Lite | 올린 사진을 보고 1인칭 여행기 초안을 쓴다 |

- **모델 선택 이유:** 이 계정에서 실제로 호출되는 모델 중 요금이 가장 낮다(100만 토큰당 입력 $0.25 / 출력 $1.50). 더 싼 2.5 Flash-Lite는 신규 키에 제공되지 않는다. 추론(thinking) 토큰은 0으로 끄고, 코스 후보도 540곳 전부가 아니라 40곳만 보낸다.
- **해설·검열·사진 검사에는 쓰지 않는다.** 해설은 공공 데이터 원문이 근거여야 하고, 검열은 키워드·개인정보 규칙이 결과를 예측할 수 있어서다. 비용과 실패 지점도 그만큼 줄어든다.
- **AI가 멈춰도 앱은 멈추지 않는다.** 코스는 규칙 기반으로, 해설은 템플릿으로 계속 동작한다.

## 5. 어떻게 만들었나

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 | Next.js 16 App Router, React 19, TypeScript | 서버에서 키를 다루고 화면은 모바일 우선으로 그린다 |
| 데이터 | Supabase(PostgreSQL·인증·파일 저장소) | 관광지 캐시, 일정·스탬프·커뮤니티 저장, 이미지 업로드를 한 곳에서 |
| 관광 데이터 | 한국관광공사 TourAPI, 국가유산청 | 공모전 필수 데이터이자 정보의 근거 |
| 지도 | 카카오 지도 SDK, 카카오 로컬, 카카오 모빌리티 | 국내 도보·대중교통 경로 품질과 한국어 지명 |
| 배포 | Vercel | GitHub에 올리면 자동 배포, 출시 점검을 통과해야 빌드 |
| 설치 | PWA(서비스워커·매니페스트) | 앱 마켓 심사 없이 홈 화면 설치, 오프라인 대비 |

**보안과 개인정보:** 모든 외부 키는 서버에만 둔다. 위치는 동의를 받은 뒤 현재 위치 표시와 스탬프 검증에만 쓰고 원시 기록은 저장하지 않는다. 서비스워커는 공개 관광 정보만 캐시하고 일정·장바구니·커뮤니티 같은 개인 데이터는 캐시하지 않는다.
