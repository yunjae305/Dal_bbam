## 이번 결정: 쇼츠 영상은 추후 추가

사용자 결정에 따라 쇼츠 **영상 피드**는 실제 영상이 준비될 때까지 감춘다. 데이터와 관리자 등록
기능은 그대로 두고, 사용자 화면에만 안내 문구를 띄운다.

- 스위치: `FEATURE_SHORTS`. **기본값은 꺼짐**(변수를 넣지 않으면 안내 문구). `true`/`1`/`on`일 때만 피드가 열린다.
- 안내 문구: 한국어 "쇼츠 영상은 추후 추가 예정입니다."와 영어·일본어·중국어 번역 (`src/shared/ui-messages.ts`).
- 같은 화면의 **방문자 스토리(FR-SNS-002)는 계속 노출**된다. 감추는 것은 영상 피드와 태그 필터뿐이다.
- 출시 점검(`release:check`)은 피드가 꺼져 있으면 게시된 영상 0건이어도 통과한다. 켜져 있으면 예전처럼
  유효한 영상 1건 이상을 요구한다 (`src/backend/database-readiness.ts`).
- 영상을 넣을 때: `/admin/shorts`에서 등록 → `FEATURE_SHORTS=true` → 재배포. 등록 규격은
  [영상 운영 안내](shorts-content-workflow.md)를 따른다.

### PWA (운영 빌드에서 확인)

`npm run build` 후 `next start`로 띄우고, `adb reverse --remove`로 실제로 연결을 끊어 확인했다.

- 설치 안내 화면 `/install`과 "홈 화면에 설치" 버튼 노출, `manifest.webmanifest`·아이콘 4종 200 응답.
- 연결을 끊은 뒤 `/places/126166`과 `/offline` 모두 오프라인 화면으로 대체되고, **미리 열어 둔 관광지
  (경주 불국사·경주 첨성대)의 저장된 정보가 표시**된다.
- 캐시에 남는 API는 `/api/home`과 `/api/places…` 공개 조회뿐이다. 일정·장바구니·커뮤니티·스탬프 같은
  **개인 데이터는 캐시에 들어가지 않는 것을 확인**했다(`Authorization` 요청과 `public`이 아닌 응답은 캐시 제외).
- 개발 서버에서는 `/offline`의 스크립트 청크가 캐시되지 않아 저장된 관광 정보가 비어 보인다. 운영 빌드에서는
  정상이므로 이 판정은 운영 빌드 기준으로 한다.

## 남은 작업

1. **카카오 콘솔에 운영 도메인 등록.** `https://dal-bbam.vercel.app`이 아직 미등록이라 운영 배포에서 지도 SDK가
   401 `domain mismatched`를 반환한다. 콘솔 등록만으로 해결되며 재배포는 필요 없다. 카카오 로그인
   Redirect URI(`https://dal-bbam.vercel.app/api/auth/kakao/callback`)도 같이 등록한다.
2. **Supabase Auth Redirect URLs**에 `https://dal-bbam.vercel.app/**` 추가 — 구글 로그인 복귀 경로.
3. **관광지 이름의 다국어 데이터.** UI는 4개 언어로 전환되지만 `place_translations`에는 영어 1행뿐이라
   목록과 지도에 한국어 이름이 그대로 보인다. 원인은 호출량이 아니라 권한이다 — **TourAPI 키가 국문
   서비스(KorService2)에만 등록돼 있어** 영문·일문·중문 서비스가 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`를
   돌려준다. 공공데이터포털에서 해당 서비스를 활용신청해 승인되면 같은 키로 동작하고,
   `scripts/sync-place-translations.mjs --apply`가 목록 조회(언어당 수십 회)로 이름을 채운다.
4. **쇼츠 영상 등록 후 `FEATURE_SHORTS=true`** 설정.
5. 실기기(안드로이드 실물·iOS Safari) 설치와 재생, 동시 접속 100명(NFR-PERF-004)은 이번 범위에서 확인하지 않았다.
