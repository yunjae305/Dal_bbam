# 커뮤니티 사용자 흐름

## 1. 둘러보기

```text
홈의 커뮤니티 진입
  → 전체 최신 피드
  → 검색 또는 지역·카테고리 필터
  → 게시글 선택
  → 상세 확인
  → 북마크
     ├─ 로그인 상태: 저장 후 상태 유지
     └─ 비로그인 상태: 로그인 안내
```

## 2. 글 작성

```text
목록의 글쓰기 버튼
  → 로그인 확인
  → 카테고리 선택
  → 장소·지역 선택
  → 사진 선택(선택 사항)
     → 업로드
     → 파일·안전·개인정보 검사
  → 제목·본문 작성
  → 카테고리별 별점 입력
  → 게시 요청
     ├─ 성공: 새 글 상세 또는 목록으로 이동
     ├─ 입력 오류: 해당 필드에 안내
     ├─ 검사 거부: 수정 가능한 안내
     └─ 검사 장애: 정책에 따른 재시도 안내
```

AI 사진 스토리는 승인된 사진이 있을 때만 제안한다. 결과는 편집 가능한 초안이며 사용자가 게시 버튼을 눌러야 공개된다.

## 3. 수정·삭제

```text
본인 글 상세
  → 더 보기
     ├─ 수정
     │   → 기존 값 불러오기
     │   → 변경
     │   → 재검사
     │   → 저장
     └─ 삭제
         → 확인
         → 게시글·연결 미디어 정리
         → 목록으로 이동
```

## 4. 상태 정의

| 상태 | 화면 처리 |
|---|---|
| 최초 로딩 | 카드 스켈레톤 3개 |
| 필터 로딩 | 기존 결과 유지 + 작은 진행 표시 |
| 빈 목록 | 필터 초기화와 글쓰기 CTA |
| 목록 오류 | 오류 설명과 재시도 |
| 업로드 중 | 진행 표시, 중복 제출 방지 |
| 검사 거부 | 원인 범주를 과도하게 노출하지 않고 수정 안내 |
| 네트워크 오류 | 입력값 유지, 재시도 제공 |
| 미저장 닫기 | 작성 내용 폐기 확인 |
| 권한 없음 | 로그인 또는 소유권 안내 |

## 5. API 의존사항

| 사용자 행동 | 현재 API | 추가 확인 |
|---|---|---|
| 목록 | `GET /api/community` | 검색·cursor·지역 필터 계약 |
| 작성 | `POST /api/community` | 카테고리별 rating 규칙 |
| 상세 | 없음 | `GET /api/community/[id]` 필요 |
| 수정 | `PATCH /api/community/[id]` | category, rating null, media 수정 계약 |
| 삭제 | `DELETE /api/community/[id]` | Storage 객체 정리 |
| 북마크 | `PUT /api/community/[id]/bookmark` | 비로그인 안내와 필터 조회 검증 |
| 사진 | `/api/community/uploads/*` | 1장/5장, 취소한 업로드 정리 |
| AI 초안 | `POST /api/community/story` | 선택 기능 및 장애 상태 |
